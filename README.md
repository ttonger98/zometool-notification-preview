# Zometool 消息通知中心交互原型

需求同步版本：2026-09-18。沿用原 GitHub Pages 地址。

## 体验

首页按个人成果、首次被跟拼、官方通知依次展示。关闭或跳转返回后继续下一条。点击消息入口体验分类、聚合详情、已读、删除与业务跳转示意。

右上角「体验设置」提供新的业务事件、体验时钟、前后台切换、两次/两小时 Push 轮次、重启 APP、异常状态和双窗口同步演示。

- 站外 Push 在原型内以通知卡片模拟；示例使用独立体验时钟。
- 状态保存在本浏览器。双设备演示使用同一浏览器的两个标签页与账号级共享记录。
- 首页背景与业务目标页为示意；正式业务页面沿用 APP 现有流程。
- 本版使用新的示例状态，不覆盖旧版浏览器体验记录。
- 静态原型承载交互评审；正式服务端、设备推送和真实审核服务由产品开发接入。

## 本地验证

```sh
python3 -m http.server 8946 --bind 127.0.0.1
node --test tests/*.test.mjs
```

`model.mjs` 是三个触达渠道共用的状态模型。`app.mjs` 负责页面操作和本地模拟。

## 已确认的展示基线

消息中心沿用原型 `fd7d743` 的适配：全屏、安全区、横屏三栏比例、字体、操作按钮和媒体区域。

- `center.css` 保留原版样式原文；`center-view.mjs` 使用对应页面结构。
- 互动消息的造型／作品缩略图位于「来自」一行右侧；跟拼作品和批量造型沿用原有展示区域。
- 首页弹窗与评审控制独立呈现；夸一夸展示互动概述、去重用户头像与昵称，共创达人评论展示具体评论内容。
- 运行 `node --test tests/*.test.mjs`，验证消息逻辑与展示基线。

## 创作反馈规则

- 五项个人成果包括入库、合集入选、共创达人、成长之星及首次被跟拼，不计普通 Push 发送次数，也不受1分钟间隔限制。仍遵守通知权限、07:00—21:00发送时段及仅在后台发送的条件。
- 普通 Push 共用每轮最多2次的发送次数，每轮从第一条实际发送时计时2小时。点击任意 Push 即清零次数；下一条普通 Push 仍须与上一条至少间隔1分钟。
- 等待发送时：原四类个人成果优先，其次首次被跟拼，再按官方通知、共创达人评论、其他互动、审核调整结果的顺序处理。先比较大顺位，再比较类型优先级；类型优先级相同才按时间取最新。成长之星与共创达人同级。
- 静默结束每位用户最多补发一条；其他消息和符合条件的首页弹窗保留，不逐条补发 Push。
- 首次被跟拼按创作者仅一次，审核通过才计入，同时收到多件跟拼作品时取审核通过最早的一件。生成独立的首次被跟拼消息，之后的新跟拼不加入这条消息。专属 Push 与普通跟拼 Push 不重复发送。
- 消息中心只向生成不足1小时的未读消息合并新互动。原消息已读、删除或满1小时后，新互动另建消息；已读消息不恢复未读。
- 同一用户对同一内容的点赞、收藏，以及对同一账号的关注，分别只在首次发生时通知，不按天重置。
- 打开消息详情或成功跳转通知配置的目标页后，按整条消息已读处理。跳转失败保持原阅读状态，但点击 Push 仍清零发送次数。
- 多人粉丝 Push 进入对应消息详情；多人夸一夸进入作品详情并定位本条 Push 中最新的夸一夸。
- 个人成果的待展示记录不随90天消息清理而丢失；成功打开详情或跳转目标页、关闭弹窗、删除消息或目标失效后结束。

- 未处理就离开首页或退出时，保留该条提醒；下次进入首页时，剩余提醒与新增提醒重新排序。官方通知每次完整启动最多弹一条。

## 定向评审入口

- `?demo=priority`：成长之星与共创达人同级、其余成果及官方通知连续展示。
- `?demo=first-follow-center`：独立的首次被跟拼消息详情。
- `?demo=first-follow-push`：首次被跟拼专属 Push。
- `?demo=fans-push`：多人新增粉丝 Push 与整条已读。
- `?demo=praise-push`：多人夸一夸 Push 与评论定位。
- 体验设置中的「连续成果与首次跟拼」：跳转后返回首页，继续展示下一条成果。

各定向入口使用独立示例状态，不覆盖普通入口的体验进度。`V1.0` 标签保留原回滚版本，不随更新移动。
