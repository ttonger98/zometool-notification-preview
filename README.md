# Zometool 消息通知中心交互原型

需求同步版本：2026-09-23（官方通知弹窗配置化）。已同步飞书正文、模板表与本次决策，并重新发布 GitHub Pages。

## 体验

首页先展示一条符合条件的官方通知（按运营优先级、覆盖标签与展示次数判断），再按四类个人成果、首次被跟拼的顺序展示。个人成果弹窗展示即结束该条提醒，其他设备与重启都不再弹；同一停留内连续关闭2条个人成果后暂停个人成果连弹。点击消息入口体验分类、聚合详情、已读、删除与业务跳转示意；未读数量只在左侧分类角标展示，入选消息中的合集名称可直接点击。

右上角「体验设置」提供新的业务事件、体验时钟、前后台切换、两次/两小时 Push 轮次、重启 APP、异常状态、取消最近一条互动和双窗口同步演示。

- 站外 Push 在原型内以通知卡片模拟；示例使用独立体验时钟。
- 状态保存在本浏览器。双设备演示使用同一浏览器的两个标签页与账号级共享记录。
- 首页背景与业务目标页为示意；正式业务页面沿用 APP 现有流程。
- 本版使用新的示例状态，不覆盖旧版浏览器体验记录。
- 静态原型承载交互评审；正式服务端、设备推送和真实审核服务由产品开发接入。

## 本地验证

```sh
python3 -m http.server 8946 --bind 127.0.0.1
node --test tests/*.test.mjs
```

`model.mjs` 是三个触达渠道共用的状态模型。`app.mjs` 负责页面操作和本地模拟。

## 已确认的展示基线

未读角标：只要未读就计入，作品删除、造型下架、成果撤销等目标失效消息仍计入，直到已读或删除；“系统消息”“互动消息”分类角标显示该分类未读数。消息中心列表不展示“已读／共”统计行。

消息中心沿用原型 `fd7d743` 的适配：全屏、安全区、横屏三栏比例、字体、操作按钮和媒体区域。

- `center.css` 保留原版样式原文；`center-view.mjs` 使用对应页面结构。
- 互动消息的造型／作品缩略图位于「来自」一行右侧；跟拼作品和批量造型沿用原有展示区域。跟拼消息详情只展示各位跟拼者的作品，不展示跟拼者头像和昵称。
- 首页弹窗与评审控制独立呈现；夸一夸展示互动概述、去重用户头像与昵称，共创达人评论展示具体评论内容。
- 运行 `node --test tests/*.test.mjs`，验证消息逻辑与展示基线。

## 创作反馈规则

- 五项个人成果包括入库、合集入选、共创达人、成长之星及首次被跟拼，不计普通 Push 发送次数。个人成果Push之间至少间隔1分钟，与普通Push的间隔分别计算；仍遵守通知权限、07:00—21:00发送时段及账号级前后台条件。
- 普通 Push 共用每轮最多2次的发送次数，每轮从第一条实际发送时计时2小时。点击任意 Push 即清零次数；下一条普通 Push 仍须与上一条至少间隔1分钟。
- 等待发送时：官方通知、四类个人成果、首次被跟拼、共创达人评论、其他互动、审核不通过依次处理。先筛选当前满足发送条件的消息，再比较顺位和类型优先级；同级取最新。成长之星与共创达人同级，其后为作品入选合集、造型正式入库。官方通知仍占普通Push次数，不阻挡符合条件的个人成果Push。
- 跨夜等待消息总共最多发送一条Push，不逐日发送积压消息。其余站内消息和有效弹窗保留；白天错过的普通互动不因跨夜获得自动发送资格。
- 首次被跟拼按创作者仅一次，审核通过才计入，同时收到多件跟拼作品时取审核通过最早的一件。生成独立的首次被跟拼消息，之后的新跟拼不加入这条消息。专属 Push 与普通跟拼 Push 不重复发送。
- 消息中心只向生成不足1小时的未读消息合并新互动。原消息已读、删除、已停止提醒或满1小时后，新互动另建消息；已读消息不恢复未读。内容失效停止提醒后，内容恢复也不恢复提醒。这里的“停止提醒”指消息已被查看、删除、一键已读或内容失效，收到过 Push 不算停止提醒。已发出 Push 不影响继续合并（新增粉丝消息除外）；生成不足1小时内再次收到新互动并满足条件时，可再次发送 Push，每次只包含尚未提醒、也未被查看的互动。
- 普通互动只在新互动发生时检查其所属消息，不因时间恢复、退出APP或重新开启通知自动发送旧互动；批量重复回调不算新互动，不触发发送判断。满足发送条件时，将同条消息内尚未通过Push提醒、也未被查看的有效互动一起计入，不带动其他旧消息发送。
- 跨夜等待消息恢复发送后总共最多1条Push，未选中的跨夜互动不再参与之后的Push文案；跨夜候选暂不满足条件时保持等待，不影响当天新消息按各自规则判断。
- 互动被取消时保留站内历史记录，该互动不再计入尚未发送的Push和弹窗；同条消息内其他有效互动照常判断。
- 同一用户对同一内容的点赞、收藏，以及对同一账号的关注，分别只在首次发生时通知，不按天重置。用户对自己作品、跟拼作品或造型的点赞、收藏、分享、夸一夸，以及跟拼自己的造型，不生成通知。
- 同一用户对同一造型只能上传一件跟拼作品，首次审核通过后通知原造型作者一次；修改、删除重传或再次审核通过不重复通知。不同用户或不同造型分别判断。
- 审核不通过通知作品或跟拼作品的上传者，按提交内容类型进入对应修改入口；成功重新提交时，停止上一轮尚未发送的修改提醒。上一轮通知保留原调整原因，主按钮按提交内容类型进入对应修改入口，按当前审核状态展示，审核中不提供重复提交；再次不通过生成新通知，通过不向上传者发结果通知。首次审核通过后，原造型作者收到跟拼反馈。
- 打开消息详情或成功跳转通知配置的目标页后，按整条消息已读处理。跳转失败保持原阅读状态，但点击 Push 仍清零发送次数。
- 粉丝消息发出Push后停止合并，新粉丝另建消息。按发送时人数固定跳转：单人进入该粉丝主页，多人进入关联消息详情。多人夸一夸进入作品详情并定位本条Push最新的有效评论；该评论删除时不定位。
- 一键已读覆盖当前分类全部消息，包括未加载消息；“全部”覆盖所有分类。停止相关待发Push和首页弹窗，不重置普通Push次数。
- 个人成果的待展示记录不随90天消息清理而丢失；弹窗展示后即结束该条提醒，查看、删除、一键已读或目标失效也结束提醒。旧消息已清理时，展示弹窗不会重新生成消息或未读角标。
- 弹窗仅有关闭和主按钮。个人成果展示时即停止该条待发Push、结束提醒，关闭仅收起弹窗、不改变阅读状态；官方通知关闭只结束本次展示，是否再次展示按时间、覆盖标签与展示次数判断。主按钮成功跳转才标为已读，失败时当前弹窗保留可重试。
- 官方通知到期后停止尚未发送的Push和待展示弹窗，消息仍保留原文案和阅读状态至生成满90天。目标页说明“活动已结束”等状态，消息中心不加结束标记；运营主动下线仍移除通知。

- 未处理就离开首页或退出时，保留该条提醒；下次进入首页时，剩余提醒与新增提醒重新排序。官方通知每次完整启动最多弹一条。
- 官方通知弹窗配置：优先级（数字小者优先，未配置时按类型顺序）；覆盖用户标签（系统维护，留空表示全部用户）；每日展示次数与累计展示次数（按“用户×该通知”计算，跨设备按账号累计，每日按北京时间0点重置，开关关闭表示不限制）。新建官方通知默认累计展示次数为1，即只展示一次。
- 官方通知在弹窗展示时间内每次完整启动可再次参与判断，同一次启动不重复弹同一条；达到次数上限或不再命中覆盖标签时停止弹窗，站内消息保留。弹窗展示即停止该条尚未发送的Push，已发出的Push不撤回。
- 同账号任一设备正在使用APP，所有设备暂不接收Push；只投递最近使用、仍登录且允许通知的一台，“最近使用”按各设备最近一次前台有效上报时间判断。个人成果弹窗在有最新使用数据、正在使用的设备上展示，展示即结束提醒，其他设备不再展示同一条。
- 新建官方通知的Push、首页弹窗默认关闭，分别开启。官方和审核不通过在发送条件恢复后重新判断；官方通知发布后不支持修改，需要调整时停止后重新新建。
- Push以推送服务确认受理为发送成功；确认失败不计次数、保留待发，结果未知先查询结果，不重复发送。设备前台状态以最近一次有效上报为准，连续5分钟未上报按已离开APP处理。
- 自行进入业务页不处理消息；通过关联通知成功进入失效说明页算已读，网络失败不算。
- 内容恢复不恢复已停止的提醒；合并跟拼中部分作品失效只排除该件，首次庆祝不更换作品。
- 成长之星标题、Banner及目标绑定获选年月，不随体验时钟改变。

## 定向评审入口

- `?demo=priority`：官方通知优先，成长之星与共创达人同级，其余成果依次展示。
- `?demo=first-follow-center`：独立的首次被跟拼消息详情。
- `?demo=first-follow-push`：首次被跟拼专属 Push。
- `?demo=fans-push`：多人新增粉丝 Push 与整条已读。
- `?demo=praise-push`：多人夸一夸 Push 与评论定位。
- `?demo=expired-official`：到期官方通知仍可查看，目标页显示活动已结束。
- `?demo=template&type=growth_star&channel=popup`：指定类型与渠道的模板展示；渠道支持 `center`、`push`、`popup`。
- 体验设置中的「连续成果与首次跟拼」：跳转后返回首页，继续展示下一条成果。

各定向入口使用独立示例状态，不覆盖普通入口的体验进度。`V1.0` 标签保留原回滚版本，不随更新移动。
